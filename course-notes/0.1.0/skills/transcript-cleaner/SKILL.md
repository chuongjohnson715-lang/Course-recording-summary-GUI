# 语音转录清洗 Skill

## 核心原则

1. **时间戳是生命线。** 下游分析（如 course-assessment-analyzer）的每一条证据都依赖时间戳引用。清洗后的每个段落必须保留或推导出一个时间戳锚点，格式统一为 `MM:SS` 或 `HH:MM:SS`。
2. **清洗 ≠ 改写。** 只删除无意义填充、修正明显的识别错误；绝不改写老师的观点，绝不删除判断信号词（"可能"、"大概"、"应该"、"一定"），绝不脑补听不清的内容。
3. **不确定就标记，不猜测。** 识别模糊处用 `[听不清]` 或 `[识别存疑:原文]` 标记，交给下游的置信度机制处理。

## 输入

课堂录音的 ASR 转录文件，常见来源与格式：

| 来源 | 典型格式 | 特点 |
|------|----------|------|
| SenseVoice / FunASR | txt，行首带 `[00:08:32-00:08:47]` | 标点较少，口语词多，同音错字多 |
| 讯飞听见 | txt/docx，带说话人标签 | 分段较好，仍有口水词 |
| 通义听悟 | txt/md，带章节摘要 | 保留其章节结构但重新校验 |
| 剪映/飞书妙记 | srt/vtt/txt | 逐句时间戳，碎句多需合并 |
| 纯文本无时间戳 | txt | 见"第 4 步：无时间戳处理" |

> **可选前置（录音改名）**：若用户给的是原始录音文件、且尚未按课表改好名，可在清洗前把录音改名——
> 依据录音文件名时间戳（`yyyyMMdd_HHmmss`）判定星期与节次，对照课表 `.xls`（周课表 + 周次过滤，开学日 2026-08-31）
> 重命名为「课程名_时间戳」；面试/无匹配的录音保留原名。完整改名逻辑见配套监控脚本
> `sensevoice/watch_and_transcribe.py` 的 `rename_by_schedule`（含 dry-run 开关）。这一步不影响后面的清洗正文。

## 处理流程

### 第 0 步：按课表改名（可选）

若前面的录音监控脚本没做改名（例如用户直接甩了个 `20261008_100444.m4a` 过来），先按时间戳查课表给录音改名，
产出 `「课程名_时间戳}.m4a` 格式的新文件名，这样后续清洗稿/分析文件的命名前缀（「课程名-日期」）才有依据。
改名不影响转录内容，仅用于统一命名。此步可跳过，若跳过则从原始文件名推断课程名并注明"推断"。

### 第 1 步：读取与格式识别

读取用户提供的转录文件，判断来源格式。若为 srt/vtt，先解析为"时间戳 + 文本"序列。

### 第 2 步：清洗（细则见 references/cleaning-rules.md）

按以下顺序执行，每条规则的边界必须严格遵守：

1. **去口水词**：删除纯填充词（嗯、啊、呃、那个那个、就是就是 等）。**红线**：表判断/不确定性的词（可能、大概、应该、好像、听说、我觉得）一律保留——它们决定下游的 confidence 与"明确/可能"分类。
2. **修正识别错误**：只修正「高置信度同音/近音错字」，修正依据（满足其一即可）：
   - 上下文语义明显指向另一词；
   - 命中 references/cleaning-rules.md 的常见错误表；
   - 属于当前课程领域的术语（如 "洗牌" → "Shuffle"、"海杜普" → "Hadoop"）。

   标注格式：该词首次出现时写 `修正词[原:识别词]`，后续直接写修正词。无法确定修正目标时保留原文并标 `[识别存疑:原文]`。
3. **补标点与断句**：按语义补全标点，将碎句合并为完整句。不得合并改变原意的句子。
4. **标记低置信度**：听不清 → `[听不清]`；整段混乱 → 段尾标 `⚠️[低置信度片段]`。

### 第 3 步：结构化分段

- 按**主题**将全文切分为若干小节（通常 3~10 个），每个小节给一个概括性标题。
- 小节标题行携带覆盖时间范围，格式：`## [08:32-15:47] MapReduce 执行流程`。
- 小节内按段落组织，每个语义单元在行首保留起始时间戳，格式：`**08:32** 老师说……`。
- 若原始转录可区分说话人（老师/学生），保留说话人标注；无法区分时默认全部为老师讲授，仅在能明确识别时标 `[学生提问]`。

### 第 4 步：无时间戳处理（仅当原文完全无时间戳）

- 不得编造具体时间戳。
- 改用顺序锚点：`[段落-01]`、`[段落-02]`……，并在文件头部注明「原始转录无时间戳，锚点为段落序号」。

### 第 5 步：输出

输出一个 Markdown 文件，命名：`{课程名或主题}-{日期}-cleaned.md`。课程名与日期未知时向用户确认；用户不回复则从文件名推断并注明"推断"。

文件头部固定为元信息块：

```markdown
---
source: 原始文件名
asr_engine: 推断的 ASR 来源（SenseVoice/讯飞/通义/剪映/未知）
date: 课程日期（未提供则"未提供"）
course: 课程名（未提供则"未提供"）
has_timestamps: true/false
low_confidence_segments: 数量
---
```

正文为结构化小节。文件末尾附「清洗说明」：修正次数统计、`[识别存疑]` 与 `[听不清]` 位置清单。

输出后向用户简要汇报：修正了多少处、有几处存疑/听不清、时间戳是否完整，并**主动询问是否继续用 course-assessment-analyzer 做课程重点分析**。

## 质量红线（违反即返工）

- 丢失任何原始时间戳 → 返工。
- 删除/改写了"可能"、"应该"等判断词 → 返工。
- 将 `[听不清]` 内容脑补为通顺文本 → 返工。
- 修正术语但不标注原识别词 → 返工。
